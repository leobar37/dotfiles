# Naming and storage for reports

`reports/` mirrors `.reviews/`. Both folders are **gitignored** so
durable runs never pollute the repo. This convention is enforced by
adding `reports/` to the repo's `.gitignore`, exactly as `.reviews/`
already is.

## File name

Pattern:
```
<scope>-<topic>-report.md
```

Components (all kebab-case, lowercase):

- `scope` — project, app, or domain the report is about. Examples:
  `avileo`, `elena`, `gymspace`, `tari-infra`, `leonbit-core`.
- `topic` — short caption for what is being reported. Examples:
  `business-assistant-admin`, `catalog-editor`, `auth-flow`,
  `billing-edge-cases`.
- Always suffix `-report.md`.

**Do NOT include a date in the report filename.** The "generated on"
timestamp is recorded in the report header metadata. A date suffix
(`-20260615`) is reserved for **snapshots** of mutable reports; the
canonical doc carries no date.

### Examples

- `reports/avileo-business-assistant-admin-report.md`
- `reports/elena-assistant-admin-report.md`
- `reports/leonbit-auth-flow-report.md`
- `reports/tari-infra-image-gen-quota-report.md`

## Storage location

Default: `<repo>/reports/` — a `reports/` directory at the root of the
repository the report is about. The folder must be **gitignored**.

If the user invokes from a project that already has `reports/`, drop the
file there. If the working directory is not a repo, or the user
explicitly asks for a different location, override with `--out=<PATH>`
(as described in the skill). Avoid `docs/reports/`, `notes/`, and the
repo root — keep reports together.

When the report spans multiple repos, put the report in the most
relevant repo and reference the others from the **References** section.

## Gitignore convention (mandatory)

Add to the repo `.gitignore`, next to `.reviews/`:

```gitignore
# AI-generated reports (admin docs, audits, investigations, feature writeups)
# Generated by the `report` skill (~/.agents/skills/report).
reports/
```

Companion files (`.checklist.json`, `.todos.md`) live in the same folder
and inherit the gitignore rule. Existing repo already had `.reviews/`
ignored; we extend the same convention to `reports/`.

## Quick resolution rules

| User says                  | Skill decides                                         |
|----------------------------|--------------------------------------------------------|
| "reporte de Avileo"        | `reports/avileo-<topic>-report.md` (ask topic)        |
| "/report elena catalog"    | `reports/elena-catalog-editor-report.md` (no date)    |
| "analyse gymspace auth"    | `reports/gymspace-auth-report.md`                      |
| (no repo context)          | Fail loud: ask for repo or pass `--out=`.             |

## Companion files (optional, but gitignored together)

Optional, only when the user asks:

- `reports/<file>.<YYYYMMDD>.checklist.json` —
  machine-readable companion that mirrors
  `references/report-checklist-template.json`. Useful when another
  skill (`feature-executor` or `code-review`) will consume it.
- `reports/<file>.todos.md` — prioritized follow-up actions.
- `reports/<file>.<YYYYMMDD>.md` — dated snapshots of an evolving
  canonical report; treat as supplementary, not as a replacement.

All companions follow the same kebab-case prefix and live next to the
report.
